# АС «Меню столовой»

Учебный проект по дисциплине автоматизации процессов жизненного цикла ПС.
Веб-приложение для публикации меню столовой на дату: администратор и
сотрудник столовой ведут каталог блюд и формируют меню, посетитель
открывает страницу и смотрит, что сегодня в столовой — без регистрации.

## Системные требования

**Для разработки(локально или на ВМ):**
- ОС: Linux (Ubuntu 22.04/24.04 проверено), также подойдёт macOS или
  Windows с WSL2 — специфичного для ОС кода в проекте нет.
- Python 3.12 (или совместимая 3.11/3.12) + модуль `venv`.
- PostgreSQL сервер 14 или новее (14/15/16 — все поддерживают частичные
  уникальные индексы и CHECK-ограничения, использованные в схеме).
- Свободное место на диске: < 200 МБ (виртуальное окружение + зависимости).
- Оперативная память: от 512 МБ свободных — Flask dev-сервер и PostgreSQL
  для такого объёма данных нетребовательны.
- Порты: 5000 (Flask dev-сервер, можно сменить) и 5432 (PostgreSQL, по
  умолчанию).
- Браузер: любой современный (Chrome/Firefox/Edge/Safari последних
  версий) — интерфейс использует только HTML/CSS без тяжёлого JS.

**Для конечного пользователя (посетитель столовой):** ничего, кроме
браузера — вход в систему не требуется.

## Установка и запуск (соответствует п. 6.5 ТЗ)

### 1. Клонировать репозиторий

```bash
git clone <адрес-репозитория>
cd menu-stolovoy
```

### 2. Создать и активировать виртуальное окружение

```bash
python3 -m venv venv
source venv/bin/activate        # Windows: venv\Scripts\activate
```

### 3. Установить зависимости

```bash
pip install -r requirements.txt
```

### 4. Создать базу данных и настроить строку подключения

```bash
sudo -u postgres psql -c "CREATE DATABASE menu_stolovoy;"
sudo -u postgres psql -c "CREATE DATABASE menu_stolovoy_test;"  

cp .env.example .env
```

### 5. Выполнить миграции до последней ревизии

```bash
export FLASK_APP=run.py                # Windows (PowerShell): $env:FLASK_APP="run.py"
flask db upgrade
```

Это создаст все таблицы и сразу заполнит справочник ролей (`admin`,
`staff`) — см. `migrations/versions/0001_baseline_schema.py`.

### 6. Создать тестового администратора

```bash
flask create-admin --username admin --password <ваш-пароль> --full-name "Иванов Иван Иванович"
```

Команда интерактивно спросит логин/пароль/имя, если не передать их
флагами.

### 7. Запустить приложение

```bash
flask run
# или: python run.py
```

### 8. Открыть в браузере

- `http://127.0.0.1:5000/menu` — публичное меню (без входа);
- `http://127.0.0.1:5000/login` — вход для администратора/сотрудника.

Проверьте: страница меню открывается, вход под созданным
администратором работает, в разделе «Блюда» можно завести первую
категорию и первое блюдо.

## Тесты

```bash
export FLASK_ENV=testing
pytest -v
```

42 теста покрывают авторизацию, права доступа по ролям, валидацию
(п. 4.2.9 ТЗ), формирование и публикацию меню, публичный просмотр и
журнал аудита — каждый тест в docstring/названии ссылается на пункт ТЗ,
который он проверяет.

Тесты используют отдельную БД `menu_stolovoy_test` (не dev-базу) и сами
создают/удаляют таблицы через `db.create_all()`/`db.drop_all()` —
поэтому запускать их безопасно в любой момент, они не портят рабочие
данные.

## Проверка миграций

Чтобы убедиться, что модели и миграция синхронны (полезно после любых
изменений в `models.py`):

```bash
flask db upgrade          # применить всё, что накопилось
flask db migrate -m tmp   # должно вывести "No changes in schema detected"
```

Если `flask db migrate` находит расхождения — значит, модель поменяли,
а миграцию забыли создать; удалите временный файл миграции из
`migrations/versions/` и создайте нормальную с осмысленным сообщением.

## Создание новой миграции (для последующих лабораторных)

```bash
# 1. поменяли модели в app/models.py
flask db migrate -m "add deadline column to tasks"   # автогенерация
# 2. открыть файл в migrations/versions/, проверить/доправить руками
#    (autogenerate не видит переименования колонок, не всегда правильно
#    ловит CHECK-констрейнты — всегда проверяйте диф глазами)
flask db upgrade                                        # применить
```

## Роли и учётные записи по умолчанию

Ролей в системе две (плюс посетитель без аккаунта):

| Роль                | Что может                                                                 |
|---------------------|----------------------------------------------------------------------------|
| **Посетитель**       | Смотреть опубликованное меню на любую дату — без входа в систему           |
| **Сотрудник (staff)**| Заводить и редактировать блюда; создавать меню на дату, добавлять/убирать блюда |
| **Администратор (admin)** | Всё то же, что сотрудник, + категории, публикация/снятие с публикации меню, учётные записи, журнал аудита |

Разграничение прав закреплено в `app/decorators.py` и напрямую следует
из Таблицы 2 ТЗ.

Тестовый администратор создаётся командой из шага 6 — своих
предустановленных паролей в репозитории нет (см. `docs/DB_STRUCTURE.md`
и п. 8.2 ТЗ про секреты).

## Запуск через Docker (Лаба 3)

```bash
cp .env.example .env
# откройте .env и задайте свой POSTGRES_PASSWORD

docker compose up --build
```

Приложение само дождётся готовности БД, применит миграции и создаст
справочник ролей при первом старте (см. `docker-entrypoint.sh`) — после
`docker compose up` достаточно открыть `http://localhost:5000/menu`.
Администратора создайте отдельно:

```bash
docker compose exec app flask create-admin --username admin --password ваш_пароль --full-name "Иванов Иван"
```

Данные PostgreSQL хранятся в именованном volume `db_data` — они
переживают `docker compose down` (без флага `-v`) и `docker compose up`
заново.
